Large-Scale PDF Extraction Pipeline

Production
Porto Real Asset · 2025 – Present Proprietary — architecture described publicly

An automated extraction pipeline for thousands of Bank Credit Notes (CCBs) — the legal documents underlying the credit fund's receivables portfolio. The pipeline converts unstructured PDFs into structured database records that feed the risk models and portfolio dashboard daily.

The problem

A FIDC (Fundo de Investimento em Direitos Creditórios) holds thousands of individual credit notes as assets. Each note is a legal PDF document containing debtor information, principal amounts, interest rates, payment schedules, and collateral details. Before this pipeline existed, analysts extracted this information manually — a process that was slow, error-prone, and couldn't scale.

The pipeline needed to handle real-world PDF variance: documents generated by different banking systems, inconsistent table layouts, multi-page structures, and occasional scan-based PDFs mixed with native digital files.

Pipeline design

CCB PDFs (inbox folder) ↓ Document classifier (native PDF vs. scanned) ↓ Extraction layer ├── pdfplumber (native digital PDFs) └── pytesseract / OCR fallback (scanned documents) ↓ Field parser (regex + heuristics per document template) ↓ Validation layer (schema checks, cross-field consistency) ↓ PostgreSQL — structured credit note records ↓ Downstream: risk models, dashboard, aging reports

What is extracted per document

  • Debtor identification (CPF/CNPJ, name, address)
  • Principal amount and disbursement date
  • Interest rate, indexer (CDI, IPCA, fixed), and spread
  • Full amortization schedule — installment by installment
  • Maturity date and number of installments
  • Guarantor information and collateral type
  • Originating bank and operation code

Engineering challenges

  • Layout variance — documents from different originators use different templates. The classifier identifies which template family a document belongs to before extraction.
  • Table reconstruction — amortization tables span multiple pages. The pipeline stitches them back together using page-boundary detection heuristics.
  • Numeric precision — financial figures must be parsed correctly (Brazilian decimal notation uses commas, not dots). Rounding errors compound when multiplied across thousands of installments.
  • Idempotency — the pipeline runs daily and re-processes updated documents. Records are upserted, not duplicated.
  • Failure handling — documents that fail validation are quarantined with a structured error log, not silently dropped. An analyst review queue surfaces extraction failures for manual inspection.

Scale and performance

The initial backfill processed 5,000+ documents accumulated since fund inception. Ongoing ingestion handles new documents as they arrive from custodians. Extraction is parallelized across CPU cores; the full backfill completed in under two hours on the production server.
